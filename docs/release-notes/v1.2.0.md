Changes since 1.0.0:

- **Running-session warning.** The dashboard shows how many `claude` sessions are running and asks before switching, since they keep the account they started with. The tray notification says the same. Only the native `claude.exe` install is detected; npm installs are not.
- **Automatic token sync.** While the tray runs, the active account's saved copy is refreshed every 30 seconds when Claude Code rotates its tokens, so a switch never restores a stale login. A login caught half-written is ignored.
- **Next account hotkey.** `Ctrl+Alt+Shift+S` (or the tray menu) switches to the next saved account, skipping expired ones. If another app already owns the hotkey, only the menu item works.
- **Labels and colors.** Name an account ("Work", "Personal") and give it a color in the dashboard. Labels also show in the tray menu.
- **Expired login detection.** An account whose refresh token has died is marked in the dashboard and tray, and is skipped by "next account". Log in again with `claude /login` and press Save current login.
- **Backup and restore.** Download the saved accounts from the dashboard and restore them later. Tokens stay encrypted with Windows DPAPI, so a backup only restores for the same Windows user; a file that fails to decrypt is rejected as a whole.
- **Remove account** from the tray menu, with a confirmation.
- Saves, switches and removals are serialized so the tray, dashboard and sync thread cannot overwrite each other.

The installer is not code-signed: if SmartScreen warns, choose More info, then Run anyway. Installing over an older version closes the running tray; open it again from the Start Menu.
